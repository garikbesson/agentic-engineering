# Update Repository Knowledge Base

Your task is to update the existing Repository Knowledge Base to reflect the current state of the repository.

The Repository Knowledge Base should remain the primary source of repository orientation for future engineering sessions.

> This playbook is self-contained.
>
> The article below explains the reasoning behind the playbook and is intended for readers who want additional background.
>
> - [Start with Orientation](../../knowledge/start-with-orientation.md)

## Objective

Review the recent repository changes and update the existing Repository Knowledge Base accordingly.

Preserve the overall documentation structure unless there is a clear reason to improve it.

Update only the documents that are affected by the recent changes.

## Repository Inspection

Inspect:

- the existing Repository Knowledge Base;
- the current repository state;
- the implementation changes made during this engineering session.

Determine how the recent implementation affects the existing documentation.

Do not rewrite the Repository Knowledge Base from scratch.

## Documentation Principles

The Repository Knowledge Base should remain:

- reusable;
- concise;
- fact-based;
- implementation-oriented;
- internally consistent.

Update repository knowledge, not feature history.

Avoid documenting implementation details that are unlikely to remain useful after future changes.

## Updating Existing Knowledge

When updating the documentation:

- preserve the existing structure whenever possible;
- modify only documents affected by the changes;
- remove obsolete information;
- update terminology if necessary;
- add newly introduced concepts when they become part of the repository architecture;
- maintain consistency across all documents.

Avoid duplicate information.

If the same concept appears in multiple documents, update every affected location.

## Structural Changes

If the existing Repository Knowledge Base structure no longer represents the repository well:

1. Explain why.
2. Propose structural improvements.
3. Wait for approval before reorganizing the documentation.

Otherwise, preserve the current structure.

## Deliverables

Before making changes:

1. Review the existing Repository Knowledge Base.
2. Identify which documents require updates.
3. Explain why each document needs to change.
4. Wait for approval.

After approval:

1. Update the affected documents.
2. Verify internal consistency.
3. Remove obsolete information.
4. Ensure the Repository Knowledge Base accurately reflects the current repository state.
